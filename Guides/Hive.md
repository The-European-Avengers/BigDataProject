# Hive Deployment and Initial CSV Load

This document describes how to deploy your full Hive setup on Kubernetes and load your first CSV file, generated by the Python scripts, into HDFS, ready for Spark processing.

## 1. Deployment and Environment Checks

### Apply the Deployment Manifest

Deploy the full stack (PostgreSQL, Hive Metastore, HiveServer, pods with the Python scripts and the shared volume):

```bash
kubectl apply -f hive-deployment.yaml
```

### Confirm All Pods Are Running

Ensure that all Hive components are healthy. The HiveServer Pod should eventually show `2/2` containers running (Hive + Python Pods).

```bash
kubectl get pods -n bd-bd-gr-05
```

### Verify Python Collector Output

Inspect the logs of the wind-collector script to confirm it retrieved data and wrote the CSV into the shared volume:

```bash
kubectl logs -n bd-bd-gr-05 deployment/hive-server -f -c wind-collector
```

Expected output includes something like:

```bash
Summary: 55/57 stations have data
Saved 42735 wind records to shared volume path: /shared-data-for-hive/2020_dmi_wind.csv
...
Complete. DMI wind data saved to: /shared-data-for-hive/2020_dmi_wind.csv
Clean data ready for Hive processing!
```


## 2. Preparing Hive

### Access the Hive Shell

Open a Hive shell session inside the Hive container (important to specify `-c hive`):

```bash
kubectl exec -it deployment/hive-server -n bd-bd-gr-05 -c hive -- hive
```

Check that Hive is responding:

```sql
SHOW DATABASES;
```

### Create the Database and External Table

Run these commands inside the Hive shell to define the database and CSV table.
The table is defined as **external** and stored as **TEXTFILE**, which preserves CSV formatting for Spark.

```sql
CREATE DATABASE IF NOT EXISTS dmi_wind;
USE dmi_wind;
```

```sql
CREATE EXTERNAL TABLE IF NOT EXISTS wind_raw_data (
  timeObserved STRING,
  stationId STRING,
  stationName STRING,
  mean_wind_speed DOUBLE
)
ROW FORMAT DELIMITED
FIELDS TERMINATED BY ','
STORED AS TEXTFILE
LOCATION 'hdfs://namenode-g5:9000/raw/initial-load/weather-wind'
TBLPROPERTIES ('skip.header.line.count'='1');
```

## 3. Loading the CSV Into HDFS

### Load via Hive (recommended)

This moves the CSV file from the shared volume (EmptyDir) into the HDFS directory backing the external table.

In the Hive shell:

```sql
LOAD DATA LOCAL INPATH '/shared-data-for-hive/2020_dmi_wind.csv'
INTO TABLE wind_raw_data;
```

### Load via Bash Script (alternative)

You can also load the data without using the Hive shell by running the automation script included in the repository. ([[/kubernetes/hive/initial-data/data_transfer_all.sh]])

Inside the Hive server Pod:

```bash
chmod +x data_transfer_all.sh
./data_transfer_all.sh
```

This performs the same load operation using `hdfs dfs -put`.


## 4. Validation

### Validate Hive Table Contents

Inside the Hive shell:

```sql
SELECT count(*) FROM wind_raw_data;
SELECT * FROM wind_raw_data LIMIT 10;
```

The row count should match the number of records written by the Python script (around 42k).

### Check the File Exists in HDFS

Exit Hive (`!quit`) and verify the CSV is present in HDFS:

```bash
kubectl exec -it deployment/hive-server -n bd-bd-gr-05 -c hive -- hdfs dfs -ls /raw/initial-load/weather-wind
```

You should see many files, one of them should be `2020_dmi_wind.csv` inside the directory.
